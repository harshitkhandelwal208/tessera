The Belief-Lattice Scrabble Engine

Tessera is a grandmaster-tier tournament Scrabble engine that completely eliminates exponential search trees. Operating over a 100% position-keyed Directed Acyclic Graph (Belief Lattice), Tessera integrates 64-bit Zobrist transpositions, prioritized Bellman relaxation, paired 2-ply draw realization, dual-headed NNUE, and an exact endgame solver.

Quick Start

Zero Setup. Build and Run in Seconds.

Tessera builds cleanly on any POSIX system with GCC or Clang with zero dependencies.

# Clone repository
git clone https://github.com/harshitkhandelwal208/tessera.git
cd tessera

# Compile high-performance engine target
make -j$(nproc)

# Run verification suite (DAWG, movegen, NNUE, DAG lattice, endgame solver)
make test

# Launch an autonomous AI vs AI demonstration match
./tessera ai-vs-ai

How to Contribute Your Compute

Contributing to Tessera is completely decentralized and lightweight. Simply run our standalone Python worker script. The client will utilize your idle CPU cores to simulate games or verify candidate patches, periodically reporting results back to the community ledger.

Option 1: One-Line Community Worker Command

# Download and execute the Tessera-Test worker client
curl -sSL https://harshitkhandelwal208.github.io/tessera/worker.py -o worker.py
python3 worker.py --concurrency 4 --user "YourName"

Option 2: Direct Worker Script Download

You can also download worker.py directly, inspect the source, and run it with custom flags:

Download worker.py (Standalone Python 3)

Command-Line Worker Options

  • --user <handle>: Sets your contributor name for the leaderboard.
  • --concurrency <N>: Number of parallel simulation threads (defaults to all CPU cores minus one).
  • --mode selfplay: Generates continuous self-play games for training the 448-dim NNUE.
  • --mode sprt --games 70: Runs a Sequential Probability Ratio Test against championship bots.
  • --mode bench: Runs a local move generation throughput and DAG simulation benchmark.

Submitting an Engine Patch for Testing

  1. Fork the official repository on GitHub: https://github.com/harshitkhandelwal208/tessera.
  2. Create a feature branch and implement your evaluation, search, or movegen modification.
  3. Ensure all tests pass cleanly via make test.
  4. Submit a Pull Request labeled sprt-request specifying candidate bounds (e.g. [0.0, 5.0] Elo). The Tessera-Test coordinator will dispatch the patch to the volunteer worker fleet!

1. Lexicon & Minimal DAWG Compression

Tournament Scrabble requires instant validation and prefix lookup over massive word lists. Tessera utilizes the complete SOWPODS 2019 lexicon (267,751 words), compressed into a Minimal Directed Acyclic Word Graph (DAWG) containing only 185,702 edges.

4-Byte Packed Edge Binary Layout

Each edge in the graph is represented in a single 32-bit unsigned integer (`uint32_t`), eliminating 64-bit pointer overhead and cache-line fragmentation:

Bit 0..23 (24 bits): Child Edge Array Index (up to 16,777,216 nodes)
Bit 24..28 (5 bits): Character code (A=0 ... Z=25)
Bit 29 (1 bit): End of Word Flag (1 if edge completes valid word)
Bit 30 (1 bit): End of Node Flag (1 if final sibling edge in node)

The compiled binary DAWG (data/dawg.bin) is strictly 742 KB in size and is loaded via zero-copy direct memory read in 0.0001 seconds.

2. Appel-Jacobson High-Throughput Move Generation

Tessera implements the classic Appel & Jacobson (1988) algorithm with optimized 32-bit bitmask precomputation, reaching sustained throughput exceeding 1,308,000 legal moves per second.

Cross-Check Bitmasks

Before traversing rows, Tessera precalculates 32-bit cross-check masks for every empty square adjacent to existing letters. If placing letter $c \in \{A..Z\}$ would form an invalid orthogonal cross-word, bit $(c - 'A')$ is cleared to 0. During recursive anchor traversal, legal placement is verified with a single CPU bitwise AND operation:

is_legal(tile) = (cross_check_mask[row][col] & (1U << (tile - 'A'))) != 0

Vertical move generation uses a transposed board representation, allowing the exact same contiguous row-traversal cache lines to be utilized for column word plays without code duplication.

3. Dual-Accumulator Static Evaluator & 8 Game Phases

Move evaluation decouples the on-board positional gain from the off-board rack leave potential, parameterized across 8 discrete game phases determined by remaining bag tiles:

TotalEquity(Move) = BoardScore(Move) + LeaveEquity(Rack \ Move)

8 Phase Buckets

  • Opening [80-100 tiles]: Premium on open stem mobility and balance.
  • Early Midgame [60-79 tiles]: Controlled board opening and vowel management.
  • Core Midgame [40-59 tiles]: Maximum scoring tempo with defensive lane closure.
  • Late Midgame [20-39 tiles]: Stem retention and tracking opponent counterplay.
  • Pre-Endgame [10-19 tiles]: Power tile shedding (Q, Z, X) to prevent stuck penalties.
  • Exhaustion [1-9 tiles]: Bag-runout defense and initiative conservation.
  • Endgame [0 tiles]: Exact deterministic outplay calculation.

4. Deep Dual-Headed NNUE Architecture

Tessera employs an Efficiently Updatable Neural Network (NNUE) designed for non-uniform imperfect-information tile dynamics.

Topology: 448 -> 128 -> 32 -> 2

Layer 1: 448 inputs -> 128 hidden neurons [Linear + ClippedReLU]
Layer 2: 128 inputs -> 32 hidden neurons [Linear + ClippedReLU]
Dual Head 1: 32 -> 1 Linear Head => Net Score Margin Spread (±50 pts)
Dual Head 2: 32 -> 1 Sigmoid Head => Win Probability P(Win) ∈ [0, 1]

In standard x86-64 environments, inner loops execute via 256-bit AVX2 Fused Multiply-Add instructions (_mm256_fmadd_ps). A portable scalar fallback is automatically activated on ARM64 and non-AVX2 hosts.

5. Belief Lattice DAG (Zero Trees)

Unlike traditional search algorithms that operate over trees and duplicate identical positions reached via transposed move orders, Tessera's search space is a 100% position-keyed Directed Acyclic Graph (DAG).

Zobrist Transposition Merging

Each board state is hashed into a 64-bit integer via precomputed pseudo-random Zobrist keys for all 225 squares and 27 tile types. Nodes are inserted into a 16,384-bucket open-addressing table. Transpositions collapse into unified graph nodes by mathematical construction.

Node Belief: B(v) = (μ_v, σ²_v, N_v)

6. Prioritized DirtyQueue Bellman Relaxation

When leaf evaluations or rollouts update node beliefs, new values propagate backward to ancestors using a binary max-heap prioritized queue:

Q(e) = MoveStatic(e) + γ · Δ_combined(e)
μ_v = max_{e ∈ OutEdges(v)} Q(e)

If $|\mu_v^{new} - \mu_v^{old}| > \epsilon$, all parent nodes are enqueued into the dirty heap. Updates ripple backward in prioritized waves until full equilibrium is achieved.

7. Persistent Bayesian Opponent Rack Modeling

Tessera maintains dynamic unigram posterior likelihoods $P(t \in \text{OpponentRack} \mid \mathcal{H})$ across the entire game. Plays that score fewer points than available open stems cause the engine to downgrade opponent possession of power tiles (S, Z, X) and elevate stem likelihoods. Tile exchanges escalate weights for burdensome consonants (Q, V, W, J).

8. The Root Court: Thompson Posterior Sampling

Stopping deliberation is formulated as a rigorous Bayesian hypothesis test rather than a fixed depth or clock allocation:

H_0: m* = argmax_m Q(m) is the mathematically optimal move

Drawing 1,000 joint posterior Gaussian samples, when $P(m^* \text{ is best}) \ge 98.0\%$, the search terminates immediately, saving critical clock time for complex midgame complications.

9. Exact Transposition DAG Endgame Solver

When the tile bag is empty and the opponent holds $\le 7$ tiles, all remaining tile identities are known with 100% certainty. Tessera activates an exact negamax solver over a 32,768-entry Zobrist transposition table with depth-indexed static move pools. Complete 8-ply endgames are solved in under 1.5 milliseconds.

10. Engine Protocol Specification
